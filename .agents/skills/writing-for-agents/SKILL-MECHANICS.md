# スキルの仕組み

[`writing-for-agents`](SKILL.md) のスキル固有部分。文書がスキルである場合に何が変わるか（フロントマター、呼び出しの選択、ルータースキル）を扱う。それ以外は `SKILL.md` の共通リファレンスである。

## 呼び出し

2つの選択肢があり、2種類の負荷を交換する:

- **モデル起動（model-invoked）スキル**は `description` を保持するため、エージェントが自律的に起動でき、他のスキルからも到達できる。名前を入力することもできる。モデル起動は常に _ユーザー起動を含む_。説明はエージェントによる発見を加えるだけで、人間による到達を奪わない。説明はスキルの最上位の参照条件付きの案内であり、常に読み込まれるよう強制される。発見可能性の代わりに、恒久的なコンテキスト負荷を支払う。内容がすべて参照のモデル起動スキルは、共有参照の置き場所にもなる。別のスキルが呼び出せるため、複数のスキルが必要とする参照を1箇所に置ける。仕組み: `disable-model-invocation` を省略し、起動分岐を含むモデル向けの説明を書く（`SKILL.md` のポインター記述規則を完全に適用する）。
- **ユーザー起動（user-invoked）スキル**は説明をエージェントの到達範囲から外す。名前を入力した人間だけが起動でき、他のスキルは起動できない。コンテキスト負荷はゼロだが、人間が索引になるため認知負荷を使う。仕組み: `disable-model-invocation: true` を設定する。`description` は人間向けになるため、トリガーの一覧を外した一行の要約にする。

エージェントが自分で到達する必要がある場合、または別のスキルが到達する必要がある場合だけモデル起動を選ぶ。手動でしか起動しないなら、ユーザー起動にしてコンテキスト負荷を支払わない。

2つのユーザー起動スキルが必要とする共有参照は、どちらにも置けない。説明がなければ、どちらも相手を起動できないからである。スキルシステムの外にある通常のファイルへ押し出す。外部参照なら、どのスキルからでも指せる。

## 呼び出しで分割する

分割の呼び出しによる切り分け（順序による切り分けは `SKILL.md` にある）では、独立して起動すべき明確な主要語がある場合（プロンプトで実際に使うトリガー語）、または別のスキルが到達する必要がある場合に、モデル起動スキルを切り出す。新しい常時読み込みの説明によってコンテキスト負荷を支払うため、その独立した到達には価値が必要である。

## ルータースキル

ユーザー起動スキルが、記憶できる量を超えて増えたとき、その認知負荷の積み上がりは**ルータースキル（router skill）**で解消する。ルータースキルは、他のスキルとそれぞれに到達するタイミングを名指しする、1つのユーザー起動スキルである。人間が覚えるスキルを1つにする。ヒントは出せるが、起動はできない。ユーザー起動スキルには説明がないため、人間以外は到達できない。
