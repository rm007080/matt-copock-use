# CONTEXT.mdの形式

## 構成

```md
# {Context Name}

{このコンテキストが何であり、なぜ存在するかを説明する1〜2文。}

## 言語

**Order**:
{その語の1〜2文の説明}
_Avoid_: Purchase, transaction

**Invoice**:
配送後に顧客へ送る支払いの請求。
_Avoid_: Bill, payment request

**Customer**:
注文を行う個人または組織。
_Avoid_: Client, buyer, account
```

## ルール

- **見解を明確にする。** 同じ概念に複数の語があるときは最善の語を選び、他の語を `_Avoid_` の下に列挙する。
- **定義を簡潔にする。** 最大でも1〜2文にする。それが何をするかではなく、それが何であるかを定義する。
- **このプロジェクトのコンテキストに固有の語だけを含める。** タイムアウト、エラー型、ユーティリティパターンなどの一般的なプログラミング概念は、プロジェクトで広く使っていても含めない。語を追加する前に問う: これはこのコンテキストだけにある概念か、それとも一般的なプログラミング概念か。前者だけを含める。
- **自然なまとまりが現れたら、サブ見出しの下に語をまとめる。** すべての語が1つのまとまった領域に属するなら、フラットなリストでよい。

## 単一コンテキストと複数コンテキストのリポジトリ

**単一コンテキスト（ほとんどのリポジトリ）:** リポジトリのルートに `CONTEXT.md` を1つ置く。

**複数コンテキスト:** リポジトリのルートにある `CONTEXT-MAP.md` が、コンテキストの場所と相互関係を列挙する。

```md
# コンテキストマップ

## コンテキスト

- [Ordering](./src/ordering/CONTEXT.md): 顧客の注文を受け取り、追跡する
- [Billing](./src/billing/CONTEXT.md): 請求書を生成し、支払いを処理する
- [Fulfillment](./src/fulfillment/CONTEXT.md): 倉庫でのピッキングと発送を管理する

## 関係

- **Ordering → Fulfillment**: Orderingは `OrderPlaced` イベントを発行し、Fulfillmentはそれを消費してピッキングを開始する
- **Fulfillment → Billing**: Fulfillmentは `ShipmentDispatched` イベントを発行し、Billingはそれを消費して請求書を生成する
- **Ordering ↔ Billing**: `CustomerId` と `Money` の共有型
```

このスキルは、どの構成を使うかを推測する。

- `CONTEXT-MAP.md` が存在するなら、それを読んでコンテキストを見つける
- ルートの `CONTEXT.md` だけが存在するなら、単一コンテキスト
- どちらも存在しないなら、最初の語が解決されたときにルートの `CONTEXT.md` を遅延作成する

複数のコンテキストがあるときは、現在の話題がどれに関係するかを推測する。不明なら尋ねる。
