# フェーズ境界

**フェーズ（phase）**は、セッション内の作業のまとまりです。グリル、implementation（実装）、QA（品質保証）などが該当します。定義は意図的に曖昧で、*「よし、これで終わり」*と思った時点でフェーズが終わります。

**フェーズ境界（phase boundary）**は2つのフェーズの間にある隙間であり、この判断を行う唯一の場所です。フェーズの途中で判断することはありません。続行するか、残りの作業をサブエージェントに分割します。フェーズの途中でコンテキストを圧縮すると、エージェントは流れを失います。

## 5つの選択肢

| Option（選択肢） | What it does（動作） |
| ---------------- | -------------------- |
| **Continue** | セッション内に留まります。コンテキストの切り替えは一切ありません。 |
| **`/clear`** | コンテキストウィンドウを空にして、最初から始めます。 |
| **`/handoff`** | プロジェクトの `handoff/YYYY-MM-DD-NN-topic.md` に記録し、別の場所や後日のセッションから作業を再開できるようにします。 |
| **Subagent** | 作業をサブエージェント固有のコンテキストウィンドウに送信し、報告を受け取ります。 |
| **`/compact`** | このコンテキストを圧縮し、要約とともに新しいセッションを開始します。 |

## ツリー

境界では上から下へ進みます。最初に **yes** になったものを選びます。

**1. このセッションで続行できますか？** 答えがyesになる理由は2つあります。次のフェーズでこのフェーズが**主要な情報源**になること、または次のフェーズを収めるだけの**[smart zone](https://www.aihero.dev/ai-coding-dictionary/smart-zone)**（スマートゾーン）が残っていること（約15万トークン）です。グリルからimplementationへ進む場合は標準的なyesです。implementationは要約ではなく、グリルの推論をそのまま必要とします。続行は何も失わず、コストもかからないので、他の選択肢より先に検討します。

**2. コンテキストは次に行うことと無関係ですか？** このセッションで行った探索、決定、行き止まりのすべてを捨ててもよいですか？ そうなら **`/clear`** です。これが盤上で最も安価な手です。時間を使わず、ウィンドウ全体を取り戻せます。`/clear` は終了ではありません。古いセッションは再開できます。

これを誤るコストは一方通行です。**関係のある**コンテキストをクリアすると、構築したものの「なぜ」を失い、いくら後から差分を読み直しても戻せません。

**3. 引き継ぐ必要がありますか？** `/handoff` で保存した記録が次の作業に必要かを判断します。例えば次の場合です:

- 同じリポジトリで、後日再開するための記録を残したいとき
- 新しい**ハーネス（harness）**（ClaudeからCodexなど）へ切り替えるとき
- 新しいディレクトリまたはリポジトリへ移るとき
- 同僚へ作業を送るとき
- フェーズの途中で本筋を乱さずに見つけた横道の作業を分岐させるとき

`/handoff` は日付付きの記録と可搬性を提供します。自動送信・コミットはしません。同じセッションの文脈を圧縮するだけなら、以下の `/compact` を検討します。

**4. 作業を離れても実行できますか？** 操作や方針の指示なしで実行できるほど範囲が明確ですか？ そうなら作業を**サブエージェント**に送り、このセッションはそのままにします。自動レビューが典型例です。エージェントは差分を読み、報告するので、あなたはその間必要ありません。

**5. それ以外は `/compact` です。** 関連するコンテキストがあり、同じハーネス、同じディレクトリで、作業の状況を追い続ける必要があるなら、ここでツリーが行き着きます。`/compact` に指示（`/compact we're going to QA this area`など）を渡すと、要約に次のフェーズで必要な情報が残ります。

`/compact` は**デフォルトであり、最初に選ぶものではありません**。上の4つの質問が、より安価または明確な選択肢であるため、最後に置かれています。ここから始めると、新しいセッションが、要約によって平坦化された判断について自信を持って誤るという失敗が起きます。

## 一次情報源と二次情報源

**Continue** 以外のすべての選択は、**一次情報源**であるセッションの経過を**二次情報源**である要約へ変えます。常に同じトレードオフがあります。

| Source（情報源） | Information（情報） | Noise（ノイズ） | Room to move（余地） |
| ---------------- | ------------------- | --------------- | -------------------- |
| 一次情報源（Continue） | Full（完全） | Lots（多い） | Little（少ない） |
| 二次情報源（`/compact`, `/handoff`） | Lossy（損失あり） | Less（少ない） | Lots（多い） |

これが質問1を最初に置く理由です。続行のコストが節約できるものを上回るときにだけ、情報の損失を払います。

## これは判断です

質問には客観的な正解がありません。それぞれに判断があり、同じ境界でも日によって異なる選択になります。価値があるのは、フェーズの途中ではなく境界で、順番どおりに問うことです。
