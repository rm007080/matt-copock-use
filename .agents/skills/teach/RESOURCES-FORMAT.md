# RESOURCES.md の形式

`RESOURCES.md` は、この話題について信頼できるリソースを厳選した一覧である。説明に使う知識は、パラメトリックな推測ではなく、ここから取り出す。知恵は、ここに列挙したコミュニティから得る。

## 構成

```md
# {Topic} リソース

## 知識

- [Book: _The Science and Practice of Strength Training_ by Zatsiorsky & Kraemer](https://example.com)
  プログラム設計と適応に関する基礎文献。次の用途に使う: 期分け、回復、強度ゾーンに関すること。
- [Article: "How Much Should I Train?" by Greg Nuckols (Stronger By Science)](https://example.com)
  量の基準値に関するエビデンスに基づくレビュー。次の用途に使う: 筋群ごとの週単位のセット目標。

## 知恵（コミュニティ）

- [r/weightroom](https://reddit.com/r/weightroom)
  ブロサイエンスを避けるよう管理された、信号の多いサブレディット。次の用途に使う: プログラムの批評、停滞のトラブルシューティング。
- ローカル: {gym name} の火曜日のストレングスクラス
  次の用途に使う: リフトのリアルタイムなコーチングフィードバック。
```

## 規則

- **信頼性の高いものだけ。** 一次資料、認められた専門家、査読済みの研究、十分に管理されたコミュニティを優先する。教育を装ったマーケティングは除外する。
- **すべての項目に注釈を付ける。** リンクだけでは3か月後には役に立たない。何を扱い、いつ参照するかを一行で加える。
- **知識 / 知恵でまとめる。** [SKILL.md](./SKILL.md) の考え方を反映する。1つのリソースが1つのグループだけに現れてもよい。
- **不足を明示する。** ミッションが必要とする領域に良いリソースがない場合は、足りないものを列挙する `## 不足` セクションを書く。これは今後の検索を導く。
- **厳しく刈り込む。** 間違っていた、浅かった、またはミッションから外れていたリソースは埋めずに削除する。平凡な資料を30個置くより、鋭い資料を5個置く方がよい。
- **コミュニティの希望を記録する。** ユーザーがコミュニティへの参加を断った場合は、今後も提案し続けないよう、ここに記録する。
