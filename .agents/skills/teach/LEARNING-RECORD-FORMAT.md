# 学習記録の形式

学習記録は `./learning-records/` に置き、連番を使う: `0001-slug.md`、`0002-slug.md` など。最初の記録を書くときにだけ、必要に応じてディレクトリを作る。

学習記録はADRに相当する教育用の記録であり、見落としやすい教訓、重要な気付き、今後のセッションを導く、ユーザーが明示した既有知識を記録する。最近接発達領域の計算に使う。

## テンプレート

```md
# {学んだことまたは確立したことの短いタイトル}

{学んだこと（または確立した既有知識）と、それが今後のセッションに重要である理由を1〜3文で書く。}
```

形式はこれだけである。学習記録は1段落だけでもよい。価値はセクションを埋めることではなく、何がすでに分かっているか、そしてそれによって次に教えるものがどう変わるかを記録することにある。

## 任意セクション

本当の価値を加える場合だけ含める。ほとんどの記録には不要である。

- **Status** フロントマター（`active | superseded by LR-NNNN`）: 以前の理解が間違っていると分かり、置き換えられたときに役立つ。
- **Evidence**: ユーザーが理解を示した方法（答えた質問、完了した演習、示した経験）。主張を後で見直す可能性があるときに役立つ。
- **Implications**: 今後のセッションで可能になること、または除外されること。見落としやすい場合に記録する価値がある。

## 番号付け

`./learning-records/` を調べて最大の既存番号を見つけ、1を加える。

## 学習記録を書く場合

次のいずれかに該当する場合に書く:

1. **ユーザーが難しい内容を本当に理解したことを示した**: 触れただけではなく、概念を正しく使える証拠がある。これにより、次に教える内容の基準が上がる。
2. **ユーザーが既有知識を明らかにした**: 「Xはすでに知っている」と言った。今後のセッションで再び教えないように記録する。主張した理解の _深さ（depth）_ も記録する。
3. **誤解が訂正された**: ユーザーが以前は間違って信じていたことと、その理由を理解した。関連する話題で今後つまずく箇所を予測できるため、価値が高い。
4. **学習に応じてミッションが変わった**: ユーザーが、思っていたものとは別のことを気にかけていると気付いた。[[MISSION.md]] に相互リンクし、更新する。

### 該当しないもの

- 単に扱っただけの内容。扱ったことは学習ではない。証拠を待つ。
- `[[GLOSSARY.md]]` に用語定義として簡潔に記録済みのもの。重複させない。
- セッションごとの活動ログ。学習記録は日誌ではなく、判断に使える洞察である。

## 置換

後の記録が以前の記録と矛盾する場合（ユーザーの理解が深まった、または訂正された場合）、古い記録を削除せず `Status: superseded by LR-NNNN` と記録する。理解がどう変化したかという履歴自体が、役立つ情報である。
