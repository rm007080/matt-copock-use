# MISSION.md の形式

`MISSION.md` はワークスペースのルートに置く。ユーザーがこの話題を学ぶ _理由_ を記録する。次に教える内容、提示するリソース、設計する演習など、すべての指導上の判断はこの文書にさかのぼれるようにする。

## テンプレート

```md
# ミッション: {Topic}

## 理由
{1〜3文。ユーザーが追いかけている具体的な現実世界の目標。このスキルを身に付けたとき、生活や仕事で何が変わるか。「Xを理解するため」のような抽象的な表現は避け、根底にある成果を掘り下げる。}

## 成功した状態
- {ユーザーができるようになる、具体的で観測可能なこと}
- {別の具体的なこと}
- {…}

## 制約
- {時間、予算、既存の予定、学習の好み、方法を制限するもの}

## 対象外
- {ユーザーが今は追いかけたくないと明示した周辺の話題。最近接発達領域を守る。}
```

## 規則

- **ワークスペースごとに1つのミッション。** ユーザーが無関係な2つのことを学びたい場合は、2つのワークスペースにする。
- **抽象より具体。** 「10月までにハーフマラソンを走る」は「体力をつける」に勝る。「チームにRustのCLIを出荷する」は「Rustを学ぶ」に勝る。
- **曖昧さを押し返す。** ユーザーが理由を説明できない場合は、何かを書く前にインタビューする。悪いミッションは、ミッションがないより悪い。
- **現実が変わったら改訂する。** ミッションは変わる。ユーザーの目標が変わったら、このファイルを更新し、古いミッションに今後のセッションを導かせない。
- **短く保つ。** `MISSION.md` が画面を越えるなら、それは羅針盤ではなく計画になっている。
