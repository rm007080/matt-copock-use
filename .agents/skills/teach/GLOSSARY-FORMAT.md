# GLOSSARY.md の形式

`GLOSSARY.md` は、この学習ワークスペースで使う正規の言葉である。すべての説明、演習、学習記録はその用語に従う。用語集を作ること自体が学習である。概念を簡潔な定義に圧縮できることは、ユーザーが理解している証拠になる。

## 構成

```md
# {Topic} 用語集

{この用語集が扱う話題と、その話題を扱う理由を1〜2文で説明する。}

## 用語

**筋肥大（Hypertrophy）**:
機械的張力と、繰り返し行うトレーニングセッション中の代謝的ストレスによって生じる筋肉の成長。
_避ける_: Bulking, getting big

**漸進的過負荷（Progressive overload）**:
負荷、量、強度によって、時間とともに筋肉への要求を体系的に増やすこと。
_避ける_: Pushing harder, levelling up

**RPE（Rate of Perceived Exertion、自覚的運動強度）**:
セットがどの程度きつく感じたかを1〜10で自己評価する値。10は失敗、8はあと2回できることを意味する。
_避ける_: Effort score, intensity rating
```

## 規則

- **ユーザーが理解したときだけ用語を追加する。** 用語集は、ユーザーが読む辞書ではなく、圧縮された知識の記録である。概念を紹介したばかりなら、正しく使えるようになるまでここに載せない。
- **立場を明確にする。** 同じ概念に複数の言葉があるときは最もよいものを選び、残りを避ける別名として列挙する。これが言葉を圧縮する方法である。
- **定義を短く保つ。** 1〜2文にする。用語が何であるかを定義し、何をするかや方法は定義しない。
- **定義の中でも用語集自身の用語を使う。** 用語が用語集に入ったら、他の定義の中も含めて、どこでも優先して使う。これにより、複雑な用語を後から理解しやすくなる。
- **自然なまとまりができたら見出しの下にまとめる**（例: `## 解剖学`、`## プログラミング`）。用語がまとまっているなら平坦な一覧でもよい。
- **曖昧さを明示する。** 広い分野で用語が緩く使われている場合は、解釈を記録する。「このワークスペースでは、'set' は常にワーキングセットを意味し、ウォームアップは別に記録する」のように書く。
- **理解が深まったら改訂する。** 1週目にユーザーが書いた定義が6週目には間違っていることがある。古い項目を残さず、その場で更新する。
