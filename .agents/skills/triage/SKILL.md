# トリアージ

プロジェクトの課題トラッカー上の課題を、トリアージ役割による小さな状態機械に沿って動かします。

このリポジトリが外部プルリクエストを依頼の窓口として扱う場合（issue-tracker設定を参照）、トリアージはPR（プルリクエスト）も対象にします。**PRはコードが添付された課題**であり、同じ役割、同じ状態、同じ機械を使います。下記ではPRの場合の差分を「PRの場合」と記します。裸の `#42` はトラッカー設定に従って課題またはPRに解決します。

トリアージ中に課題トラッカーへ投稿するすべてのコメントまたは課題は、**必ず**次の注意書きで始めます。

```
> *This was generated by AI during triage.*
```

## 参照ドキュメント

メンテナーへの確認は、グリル前後も含めて `grilling` の「Step 1: 入力を理解する」「Step 3: 1問ずつグリルする」「Step 4: 終了する」に従い、原則1問ずつ進めます。短い確認ではこれらの事実確認・質問進行・終了のルールだけを適用し、Step 2の観点一覧を使う設計インタビューは始めません。依頼を具体化するためにグリルする場合は、下記の手順4で4段階全体を使います。投稿するトリアージメモには、必要な複数の未解決質問を記載して構いません。

- [AGENT-BRIEF.md](AGENT-BRIEF.md)：持続性のあるエージェントブリーフの書き方
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)：`.out-of-scope/` ナレッジベースの仕組み

## 役割

2つの**カテゴリ**役割があります。

- `bug`：何かが壊れている
- `enhancement`：新機能または改善

5つの**状態**役割があります。

- `needs-triage`：メンテナーの評価が必要
- `needs-info`：報告者からの追加情報を待っている
- `ready-for-agent`：仕様が完全で、AFK（away from keyboard、離席中にエージェントだけで進める）エージェントが対応できる
- `ready-for-human`：人間による implementation（実装）が必要
- `wontfix`：対応しない

PRでは、同じ状態を添付コードに対して解釈します。`ready-for-agent` はブリーフが添付され、エージェントが差分の次の作業へ進むべき状態を意味し、`ready-for-human` は人間がマージできる状態を意味します。

トリアージ済みの課題には、カテゴリ役割を1つ、状態役割を1つだけ付けます。状態役割が衝突した場合は、他のことをする前にそれを示し、メンテナーに尋ねます。

これらは正規の役割名です。課題トラッカーで使われる実際のラベル文字列は異なる場合があります。対応表は提供されているはずです。なければ、ユーザーに `/setup-matt-pocock-skills` の実行を伝えてください。

状態遷移：ラベルのない課題は通常、まず `needs-triage` になります。そこから `needs-info`、`ready-for-agent`、`ready-for-human`、`wontfix` のいずれかへ移ります。報告者が返信すると `needs-info` は `needs-triage` に戻ります。メンテナーはいつでも上書きできます。通常と異なるように見える遷移は示し、先へ進む前に尋ねます。

## 呼び出し

メンテナーは `/triage` を呼び出し、自然言語で希望することを説明します。内容を解釈して実行します。例：

- 「注意が必要なものをすべて見せて」
- 「#42を見よう」（課題またはPR）
- 「#42をready-for-agentへ移して」
- 「エージェントが取り上げられるものは何？」

## 注意が必要なものを表示する

課題トラッカーに問い合わせ、古いものから次の3つのバケットに分けて提示します。

1. **Unlabeled**：まだトリアージされていない。
2. **`needs-triage`**：評価中。
3. **前回のトリアージメモ以降に報告者の活動がある `needs-info`**：再評価が必要。

PRが範囲に含まれる場合は、外部PRもこれらのバケットに含め、各行に `[PR]` または `[issue]` を付けます。探索で表示するのは**外部**PRだけです（誰を外部と数えるかはトラッカー設定が決めます）。共同作業者の進行中PRはトリアージ作業ではありません。このフィルターは探索にだけ適用します。明示的に名前を指定されたPRは、作成者に関係なく常にトリアージします。

件数と各項目の1行要約を示します。メンテナーに選んでもらいます。

## 特定の課題またはPRをトリアージする

1. **コンテキストを集める。** 課題またはPRの全文（本文、コメント、ラベル、作成者、日付。PRなら差分も）を読みます。解決済みの質問を再度尋ねないよう、過去のトリアージメモを解析します。プロジェクトのドメイン用語集を使ってコードベースを探索し、その領域のADR（アーキテクチャ決定記録）を尊重します。コードベースに対して2つの確認を行います。(a) **重複**：依頼の文言だけではなくドメイン概念によって、依頼された振る舞いの既存実装を探し、どこを調べたかを報告します。見つかった場合は、すでに実装済みの `wontfix` です（ステップ5）。(b) **過去の却下**：`.out-of-scope/*.md` を読み、この依頼に似たものを示します。

2. **推薦する。** カテゴリと状態の推薦を理由付きでメンテナーに伝え、依頼に関係するコードベースの短い概要（すでに実装されているかどうかを含む）を伝えます。指示を待ちます。

3. **主張を検証する。** グリルの前に、主張が成り立つことを確認します。バグなら報告者の手順から再現します。PRなら、差分が主張どおりであることを確認します。チェックアウトし、関連するテストまたはコマンドを実行します。確認結果を報告します。確認できた（コードパス付き）、失敗した、情報不足（強い `needs-info` の兆候）のいずれかです。確認済みであることは、より強いエージェントブリーフにつながります。

4. **グリルする（必要な場合）。** 依頼を具体化する必要がある場合は、Skill toolを「grilling」と「domain-modeling」について2回呼び出し、対話全体で原則1問ずつ質問して形にします。決定が進むたびに、ドメイン用語を研ぎ澄まし、`CONTEXT.md` / ADRをその場で更新します。

5. **結果を適用する。**
   ユーザーが途中終了した場合はこの手順へ進まず、決定事項と未決事項を要約して終えます。終了をラベル変更やコメント投稿の承認として扱いません。

   - `ready-for-agent`：エージェントブリーフのコメント（[AGENT-BRIEF.md](AGENT-BRIEF.md)）を投稿します。
   - `ready-for-human`：同じ構造のエージェントブリーフを使いますが、委任できない理由（判断、外部アクセス、設計上の決定、手動テスト）を記載します。
   - `needs-info`：トリアージメモ（下のテンプレート）を投稿します。
   - `wontfix` の場合は、**理由**に応じたコメントを付けて課題を閉じます。
     - **すでに実装済み**：変更はコードベースに存在します。存在する場所を示します。`.out-of-scope/`（これは**却下**された依頼のナレッジベースで、構築済みのものではありません）には**書かないでください**。
     - **却下（バグ）**：丁寧に説明してから閉じます。
     - **却下（機能拡張）**：`.out-of-scope/` に書き、コメントからリンクして閉じます（[OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)）。
   - `needs-triage`：役割を適用します。進捗が一部ある場合はコメントを付けてもかまいません。

## 状態の即時上書き

メンテナーが「#42をready-for-agentへ移して」と言った場合は、その指示を信頼し、役割を直接適用します。これから行うこと（役割の変更、コメント、クローズ）を確認してから実行します。グリルは省略します。グリルなしで `ready-for-agent` に移す場合は、エージェントブリーフを書くかどうかを尋ねます。

## Needs-infoテンプレート

```markdown
## Triage Notes

**What we've established so far:**

- 確認できた点1
- 確認できた点2

**What we still need from you (@reporter):**

- 報告者から必要な情報の質問1
- 報告者から必要な情報の質問2
```

グリル中に解決したことはすべて「established so far」の下に記録し、作業が失われないようにします。質問は「追加情報をください」のようなものではなく、具体的で実行可能なものにします。

## 過去のセッションを再開する

課題またはPRに過去のトリアージメモがある場合は、それを読み、報告者が未解決の質問に答えたか確認し、続行する前に更新した状況を提示します。解決済みの質問は再度尋ねません。
