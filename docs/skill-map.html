エージェントスキルの地図

次に打つのは、実線の地点だけ。

破線の内側は、その会話の中でエージェントが行うこと。枝は二つとも同じ強さで、条件に当てはまる方へ進む。あらかじめ太い道はない。地点を選ぶと歩き方の三行が開く。開いているのは一つだけ。

例は、次の五つの地点をこの順で開く。アイデアがまだふわっとしている。試作用のチャットへ渡す。見ないと決まらないことを確かめる。わかったことを、元の会話へ戻す。同じチャットで作り切る。

  • 地点 実線。自分で次に呼ぶ。
  • 内側の箱 破線。見えるが、打たない。
  • 枝 条件が真のときだけ進む。同じ強さ。
  • 歩き方 地点を選ぶと開く三行。一つだけ。

道の読み方

  • 全体の要求は docs/spec.md、構成は docs/architecture.md、技術は docs/tech-stack.md。個別の計画と実装チケットは同じ日付付き作業フォルダーへ置く。調査課題はその中の discovery/ へ分ける。
  • 後日同じリポジトリで再開する記録にも /handoff を使える。保存は毎回新しい日付・連番のファイルで、自動送信やコミットはしない。
  • グリルから必要な文書化・/to-tickets までは、同じチャットで進む。実装を分けるときは、チケットごとに新しいチャットを開く。
  • /clear と codebase-design は、この地図の箱ではない。codebase-design は /improve-codebase-architecture の会話の中で使う語彙。
