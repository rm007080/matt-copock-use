# ドメイン文書（Domain docs）

このリポジトリでは、ドメインの文脈（domain context）を1つ使う。

## 調査を始める前に

ルートの `CONTEXT.md` と、作業に関係する `docs/adr/` 内の設計判断記録（ADR）を読む。ADRには設計上の判断を記録する。

どちらかがなくても、そのまま進める。用語や判断が確定したときに、`/domain-modeling` スキルが作成する。

## 配置

- `CONTEXT.md`：ドメインの用語とその意味。
- `docs/adr/`：リポジトリに影響する判断。

## 確立された用語を使う

課題（issue）、提案、仮説、テストでは、`CONTEXT.md` に定義された用語を使う。必要な用語がない場合は、その用語を再考するか、`/domain-modeling` で扱うべき不足として記録する。

提案する変更がADRと矛盾する場合は、該当するADRを示し、矛盾の内容を説明する。
